# Leave Management System — Build Plan & Documentation

## Overview

This document covers everything needed to build the leave management feature.
It is a **self-contained addition** — no existing file is deleted or broken.
Only two existing files get small, clearly marked additions:

- `crm/urls.py` — 4 new URL lines appended
- `assetmanager/urls.py` — no change needed (crm urls already included)
- `admin_dashboard/urls.py` — 3 new URL lines appended

---

## Architecture Decision

The leave feature lives **inside the existing `crm` app** as a new model + views + templates.
This is the same pattern used for `MoneyRequest`, `MissedCall`, `HandlerReport` — all added
to `crm` without touching other apps.

No new Django app is created. No settings change needed.

---

## Database Design

### New Model: `LeaveRequest` (added to `crm/models.py`)

| Field              | Type                      | Notes                              |
| ------------------ | ------------------------- | ---------------------------------- |
| `id`             | AutoField                 | PK                                 |
| `employee`       | FK → Employee            | The applicant                      |
| `leave_type`     | CharField choices         | annual / sick / emergency / unpaid |
| `start_date`     | DateField                 | First day of leave                 |
| `end_date`       | DateField                 | Last day of leave                  |
| `days_requested` | IntegerField              | Auto-calculated on save            |
| `reason`         | TextField                 | Employee's reason                  |
| `status`         | CharField choices         | pending / approved / rejected      |
| `reviewed_by`    | FK → Employee (nullable) | Manager/admin who acted            |
| `review_notes`   | TextField (blank)         | Rejection/approval note            |
| `created_at`     | DateTimeField auto        | When applied                       |
| `updated_at`     | DateTimeField auto        | Last change                        |

### New Model: `LeaveBalance` (added to `crm/models.py`)

| Field                 | Type                      | Notes                           |
| --------------------- | ------------------------- | ------------------------------- |
| `id`                | AutoField                 | PK                              |
| `employee`          | OneToOneField → Employee | One balance record per employee |
| `annual_days_total` | IntegerField default=21   | Allocated annual leave days     |
| `annual_days_used`  | IntegerField default=0    | Approved annual days taken      |
| `sick_days_total`   | IntegerField default=10   | Allocated sick leave days       |
| `sick_days_used`    | IntegerField default=0    | Approved sick days taken        |
| `year`              | IntegerField              | The leave year (e.g. 2026)      |
| `updated_at`        | DateTimeField auto        |                                 |

**Computed properties on `LeaveBalance`:**

- `annual_days_remaining` → `annual_days_total - annual_days_used`
- `sick_days_remaining` → `sick_days_total - sick_days_used`

## Files to CREATE (brand new)

### 1. `crm/leave_views.py`

Contains all leave-related view functions. Kept separate from the 67k `crm/views.py`
to avoid merge conflicts and keep things clean.

**Views inside:**

| View                  | Method   | Who           | What                               |
| --------------------- | -------- | ------------- | ---------------------------------- |
| `apply_leave`       | GET+POST | Employee      | Submit a leave application         |
| `my_leave_requests` | GET      | Employee      | See own leave history + balance    |
| `leave_decision`    | POST     | Admin/Manager | Approve or reject a request        |
| `admin_leave_list`  | GET      | Admin         | See all pending/all leave requests |

### 2. `crm/migrations/0014_leaverequest_leavebalance.py`

Django migration file for the two new models.

### 3. `templates/crm/apply_leave.html`

Employee form to apply for leave. Extends `crm/employee_base.html`.
Shows current balance before submitting.

### 4. `templates/crm/my_leave_requests.html`

Employee view of their own leave history + remaining days.
Extends `crm/employee_base.html`.

### 5. `templates/crm/admin_leave_list.html`

Admin/manager view of all leave requests with approve/reject buttons.
Extends `crm/base.html`.

## Leave Balance Logic

- `LeaveBalance` is created automatically (via `get_or_create`) the first time
  an employee views their balance or applies for leave.
- Default: 21 annual days, 10 sick days per year.
- When a leave request is **approved**, `days_used` on the balance is incremented.
- When an approved request is **rejected after approval** (edge case), days are decremented.
- `emergency` and `unpaid` leave types do not deduct from annual/sick balance.

## Access Control

Uses the existing `role_required` decorator from `crm/decorators.py`.

| Action            | Allowed Roles                          |
| ----------------- | -------------------------------------- |
| Apply for leave   | All authenticated employees            |
| View own requests | All authenticated employees            |
| Approve / Reject  | `admin`, `hr`, `project_manager` |
| View all requests | `admin`, `hr`, `project_manager` |

## Build Order (step by step)

1. Add `LeaveRequest` + `LeaveBalance` models to `crm/models.py`
2. Create migration `0014_leaverequest_leavebalance.py`
3. Create `crm/leave_views.py` with all 4 views
4. Add import + 4 URL paths to `crm/urls.py`
5. Create `templates/crm/apply_leave.html`
6. Create `templates/crm/my_leave_requests.html`
7. Create `templates/crm/admin_leave_list.html`
8. Add nav links to `employee_base.html` and `base.html`
9. Add redirect shortcut to `admin_dashboard/urls.py` + `views.py`
10. Run `python manage.py migrate` to apply DB changes
